# Curriculum Coverage Standard

Every numbered handbook contains: a QA-first guide, test design/catalog, hands-on practice, interview Q&A and real-world scenario. The program-level QA Platform provides shared datasets, automation, evaluation sets, security/performance suites, reports, defects, CI and capstone artifacts.

| Required senior QA perspective | Where it is exercised |
|---|---|
| SUT understanding, architecture, risks/failure modes | Handbook guides 01–22 |
| strategy, scenarios, cases, test data | Guides, catalogs, practices, `QA_Platform/docs` and `test_data` |
| automation, validation, reconciliation | Handbooks 02–04, `QA_Platform/framework` and `tests` |
| negative/boundary, performance, security, reliability/recovery | Handbooks 06–12 plus platform suites |
| ML/LLM/RAG/agent evaluation | Handbooks 13–17 plus `QA_Platform/evals` |
| production investigation, metrics, quality gates | Handbooks 10, 17–20 and platform runbook/gate/report |
| senior/architect interviews and scenarios | interview + real-world files in every handbook |
| enterprise QA capstone | Handbook 22 and `QA_Platform/` |

## Definition of completion

For each handbook, the learner must produce an explicit test strategy, risk/test-case set, test data/oracle, execution evidence, release decision and a spoken senior-level explanation. Reading alone is not completion.
