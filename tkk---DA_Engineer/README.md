## 💡 Key Concepts to Know Cold

### SQL
- `RANK` vs `DENSE_RANK` vs `ROW_NUMBER` — exact difference and when each fails
- `LAG`/`LEAD` for MoM, YoY, next-event comparisons
- Running totals and 3/7/30-day moving averages
- Sessionization using LAG + gap detection
- Recursive CTEs for org hierarchy and date series generation
- Query optimization: EXPLAIN, partition pruning, broadcast joins, filter pushdown
- NULL traps: `= NULL` vs `IS NULL`, `NULLIF`, `COALESCE`

### Statistics
- p-value: what it is and what it is NOT
- Type 1 error (false positive) vs Type 2 error (false negative)
- Statistical power and why you set it to 80%
- Sample size formula — know the levers (effect size, alpha, power)
- CLT and why it justifies using z-tests/t-tests
- A/B test pitfalls: peeking, SRM, novelty effect, network interference, survivorship bias

### Product Analytics
- North Star metric framework — always state it first
- DAU/MAU stickiness ratio (> 20% = healthy)
- D1/D7/D30 retention benchmarks by industry
- Cohort analysis — what the heatmap tells you
- RFM segmentation — Recency, Frequency, Monetary
- Funnel drop-off analysis — finding the biggest leak
- Metric decomposition: Revenue = Users × Conversion × AOV

### Data Modeling
- Star schema vs snowflake schema — when to use which
- Fact table (numeric, additive) vs dimension table (descriptive)
- SCD Type 1 (overwrite) vs SCD Type 2 (versioned rows with effective dates)
- Normalization: 1NF → 2NF → 3NF — what each removes

## 🏆 What Interviewers Are Looking For

### **Technical (60% of decision)**
- ✅ Can you structure a query clearly and think out loud?
- ✅ Do you spot edge cases? (nulls, duplicates, timezone, data freshness)
- ✅ Can you define the right metric — not just calculate it?
- ✅ Do you approach business problems with data, not opinions?

### **Behavioral (40% of decision)**
- ✅ Can you quantify your past impact? (not "improved performance" — "reduced query time by 60%")
- ✅ Do you understand the business context of your analysis?
- ✅ Can you communicate findings to non-technical stakeholders?
- ✅ Do you ask clarifying questions before jumping to solutions?

## 📌 Interview Checklist

### **Before the Interview**
- ☐ Know the company's North Star metric (research their product)
- ☐ Have 3 STAR stories ready with data outcomes (%, $, X× improvement)
- ☐ Reviewed SQL window functions cold (no lookup needed)
- ☐ Can define p-value and A/B pitfalls in one sentence each

### **During the Interview**
- ☐ Clarify before writing — data source, time range, metric definition
- ☐ Think out loud — interviewers want to see reasoning, not just answers
- ☐ State trade-offs — "One concern with this approach is..."
- ☐ North Star first — before any metric or case study question
- ☐ Mention edge cases — nulls, duplicates, timezone, data lag

### **After the Interview**
- ☐ Send thank you note within 24 hours
- ☐ Note which questions caught you off-guard → revise that chapter
- ☐ Update weak areas in your study plan

## 💡 Pro Tips

1. **Type, don't copy-paste** — muscle memory matters when writing SQL live
2. **Practice explaining out loud** — "I'm using DENSE_RANK here because..."
3. **Always mention edge cases** — it signals senior-level thinking
4. **Business context first** — "Before writing the query, let me confirm what we mean by active user..."
5. **Know your numbers** — be ready to say "This query ran on 500M rows, took 4 mins in Databricks"
