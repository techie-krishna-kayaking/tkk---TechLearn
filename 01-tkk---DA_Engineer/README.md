## 📖 What This Is

A **focused interview prep system** for senior & staff Data Analyst roles at top product-based companies. Built for 10 YOE professionals targeting the **₹70–80 LPA** band. Not a tutorial. This is **competition-level preparation** with:

✅ **Advanced SQL** — window functions, sessionization, recursive CTEs, classic hard problems  
✅ **Python & Pandas** — real data wrangling, EDA workflow, cleaning patterns  
✅ **A/B Testing & Statistics** — hypothesis testing, sample size, pitfalls  
✅ **Causal Inference** — CUPED, diff-in-diff, sequential testing, switchback, propensity/IPW  
✅ **Product Analytics** — DAU/MAU, cohort, retention, funnel, RFM — exactly what gets asked  
✅ **End-to-end case studies** — "GMV is down, debug it" — full business investigation in SQL  
✅ **PySpark** — transformations, window functions, joins, optimization for Databricks  
✅ **Analytics Engineering** — dbt models/tests/docs, semantic layer, modern data stack  
✅ **BI & Semantic Modeling** — Looker/LookML, Tableau, Power BI/DAX, metric governance  
✅ **Forecasting & Applied ML** — time-series, churn/propensity, driver analysis  
✅ **Cloud Data Platforms** — BigQuery/Snowflake/Redshift/Databricks, cost & performance  
✅ **Analytics System Design** — pipelines, experimentation platform, metrics tree, data quality  
✅ **Data Modeling** — star schema, SCD Type 2, normalization  
✅ **Senior Behavioral & Leadership** — STAR-L, influence, and comp negotiation (worth 10–20 LPA)

> **Why 70–80 LPA needs more than SQL:** at 10 YOE, deep SQL/stats is *table stakes* — everyone in the loop clears it. The offer (and your level) is decided by the **senior differentiators**: causal inference when you can't A/B, owning the transformation + semantic layer, forecasting/ML literacy, system design, and staff-level behavioral + negotiation. Chapters 10–16 are those differentiators.

## 💡 Key Concepts to Know Cold

### SQL
- `RANK` vs `DENSE_RANK` vs `ROW_NUMBER` — exact difference and when each fails
- `LAG`/`LEAD` for MoM, YoY, next-event comparisons
- Running totals and 3/7/30-day moving averages
- Sessionization using LAG + gap detection
- Recursive CTEs for org hierarchy and date series generation
- Query optimization: EXPLAIN, partition pruning, broadcast joins, filter pushdown
- NULL traps: `= NULL` vs `IS NULL`, `NULLIF`, `COALESCE`

### Statistics
- p-value: what it is and what it is NOT
- Type 1 error (false positive) vs Type 2 error (false negative)
- Statistical power and why you set it to 80%
- Sample size formula — know the levers (effect size, alpha, power)
- CLT and why it justifies using z-tests/t-tests
- A/B test pitfalls: peeking, SRM, novelty effect, network interference, survivorship bias

### Product Analytics
- North Star metric framework — always state it first
- DAU/MAU stickiness ratio (> 20% = healthy)
- D1/D7/D30 retention benchmarks by industry
- Cohort analysis — what the heatmap tells you
- RFM segmentation — Recency, Frequency, Monetary
- Funnel drop-off analysis — finding the biggest leak
- Metric decomposition: Revenue = Users × Conversion × AOV

### Data Modeling
- Star schema vs snowflake schema — when to use which
- Fact table (numeric, additive) vs dimension table (descriptive)
- SCD Type 1 (overwrite) vs SCD Type 2 (versioned rows with effective dates)
- Normalization: 1NF → 2NF → 3NF — what each removes

### Causal Inference (Senior differentiator)
- CUPED — how a pre-experiment covariate cuts variance without bias
- Difference-in-differences — the parallel-trends assumption
- Sequential testing / peeking — why naïve daily checks inflate false positives
- Switchback / cluster randomization — when SUTVA breaks in marketplaces
- Propensity score matching / IPW — removing selection bias in observational data
- Method-selection: A/B → CUPED → switchback → DiD → PSM/IV/RDD

### Analytics Engineering & Modern Data Stack
- dbt layers: sources → staging → intermediate → marts
- The four workhorse tests: `unique`, `not_null`, `relationships`, `accepted_values`
- Incremental models + merge — reprocess only new data
- dbt snapshots = automated SCD Type 2
- The **semantic layer**: define each metric once, no metric drift
- ELT vs ETL; orchestration (Airflow/Dagster) + CI on modified models

### BI & Semantic Modeling
- LookML measures/dimensions/explores; `relationship` = fan-out safety
- The fan-out / double-counting trap and how to fix it
- Power BI/DAX: row vs filter context, `CALCULATE`, time intelligence
- Dashboard design: decision-first, one primary metric, always a comparison
- Metric governance: certified content, metric dictionary, RLS

### Forecasting & Applied ML
- Always beat a naive/seasonal-naive baseline; time-based holdout
- Holt-Winters / SARIMA / Prophet — trend + seasonality
- Churn/propensity: AUC vs business threshold; pick cutoff by expected value
- Key-driver analysis via regression coefficients
- Data leakage, class imbalance, calibration — the eval traps

### Cloud Data Platforms
- MPP mental model: minimize **scan** and **shuffle**
- Partitioning (filter column) + clustering/sort (high-cardinality)
- BigQuery bytes-scanned billing → no `SELECT *`, prune partitions, approx functions
- Broadcast vs shuffle joins; data skew and salting
- Lakehouse: Delta/Iceberg, ACID, time travel, medallion architecture

### Analytics System Design (Staff)
- Universal framework: clarify → reqs → design → trade-offs → failure → success
- Experimentation platform: assignment, exposure logging, SRM, guardrails
- North Star metric **tree** with paired guardrails (anti-gaming)
- Event taxonomy / tracking plan / data contracts
- Data quality: tests, freshness SLAs, anomaly detection, incident response

### Senior Behavioral & Negotiation
- STAR-L: add the **Learning** and lead with the quantified result
- Influence without authority, disagree-and-commit, ownership of failure
- Get **levelled** correctly first — comp follows level
- Negotiate **total comp** (base + bonus + equity), never anchor on current salary

### **Technical (60% of decision)**
- ✅ Can you structure a query clearly and think out loud?
- ✅ Do you spot edge cases? (nulls, duplicates, timezone, data freshness)
- ✅ Can you define the right metric — not just calculate it?
- ✅ Do you approach business problems with data, not opinions?

### **Behavioral (40% of decision)**
- ✅ Can you quantify your past impact? (not "improved performance" — "reduced query time by 60%")
- ✅ Do you understand the business context of your analysis?
- ✅ Can you communicate findings to non-technical stakeholders?
- ✅ Do you ask clarifying questions before jumping to solutions?

## 📌 Interview Checklist

### **Before the Interview**
- ☐ Know the company's North Star metric (research their product)
- ☐ Have 3 STAR stories ready with data outcomes (%, $, X× improvement)
- ☐ Reviewed SQL window functions cold (no lookup needed)
- ☐ Can define p-value and A/B pitfalls in one sentence each

### **During the Interview**
- ☐ Clarify before writing — data source, time range, metric definition
- ☐ Think out loud — interviewers want to see reasoning, not just answers
- ☐ State trade-offs — "One concern with this approach is..."
- ☐ North Star first — before any metric or case study question
- ☐ Mention edge cases — nulls, duplicates, timezone, data lag

### **After the Interview**
- ☐ Send thank you note within 24 hours
- ☐ Note which questions caught you off-guard → revise that chapter
- ☐ Update weak areas in your study plan

## 💡 Pro Tips

1. **Type, don't copy-paste** — muscle memory matters when writing SQL live
2. **Practice explaining out loud** — "I'm using DENSE_RANK here because..."
3. **Always mention edge cases** — it signals senior-level thinking
4. **Business context first** — "Before writing the query, let me confirm what we mean by active user..."
5. **Know your numbers** — be ready to say "This query ran on 500M rows, took 4 mins in Databricks"
